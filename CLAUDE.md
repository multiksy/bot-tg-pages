# tg-app — Telegram Mini App «Монтаж Reels»

Статический прототип (HTML + CSS + JS, без фреймворков) по [research.md](../research.md) и [brief.md](../brief.md), раздел 11.
Backend не подключён: загрузка видео, обработка и оплата **полностью замоканы на клиенте** — см. «Что здесь мок» ниже.

## Файлы и зоны ответственности

| Файл | За что отвечает |
|---|---|
| `index.html` | Точка входа. Разметка всех 8 экранов (splash, home, upload, processing, result, history, pricing, profile), таб-бара, нижней шторки и тоста. Подключает Telegram SDK с `telegram.org` и три скрипта в порядке `data.js → telegram.js → app.js`. |
| `css/style.css` | Вся визуальная часть: **фиксированная бренд-палитра** (тёмно-синий фон + пыльно-розовый акцент + Montserrat — синхронизировано с сайтом того же автора, см. раздел «Бренд-палитра» ниже), нативный вид (закругления, «стеклянные» карточки, металлик-кнопки), анимации переходов между экранами (`fade`/`slide`), тактильный отклик на касания, адаптация 320–430px. |
| `js/data.js` | **Единственное место, где лежат тексты и цифры продукта** — оффер, тарифы, этапы обработки, стили субтитров/музыки, мок-история клипов, юзернеймы бота. Замена контента — всегда сюда, не в HTML/JS-логику. |
| `js/telegram.js` | Обёртка над `window.Telegram.WebApp` (модуль `Native`). Пользователь, Main/Back Button, хаптики, открытие чата с ботом, шаринг, цвет системного «хрома» Telegram. Если SDK недоступен (обычный браузер) — безопасные заглушки, чтобы приложение не падало при разработке вне Telegram. |
| `js/app.js` | Роутер между экранами + вся интерактивная логика (загрузка → обработка → результат → тарифы → оплата, история, профиль). Здесь же замокан backend (таймеры вместо реального прогресса, `localStorage` вместо БД). |
| `img/*.webp` | Декоративные «жидкий металл» иконки (сердце, искра, капля, месяц, кольца), перенесённые с сайта того же автора — см. раздел «Декоративные иконки» ниже. |

## Навигация между экранами

Экраны переключаются функцией `showScreen(name, transition)` в `app.js` — она прячет все `.screen`, показывает `#screen-{name}` и запускает CSS-анимацию (`fade` — при табах, `forward`/`back` — при переходах вглубь/назад по стеку).

```
Главная (home) ──CTA──▶ Загрузка (upload) ──открыть чат──▶ Обработка (processing) ──авто──▶ Результат (result)
   ▲                                                                                             │
   └───────────────────────────── таб-бар / Back Button ◀──────────────────────────────────────┘
Главная / Мои клипы (history) / Профиль (profile) — три вкладки таб-бара, доступны всегда (кроме splash)
Тарифы (pricing) открывается из: бейджа лимита на Главной и на Результате, строки тарифа в Профиле
```

Полная таблица «экран → элементы → переходы» — в [brief.md](../brief.md#11-mini-app--экраны-и-пошаговый-план-разработки-v1).

## Где менять данные

Все правки контента и цифр — в `js/data.js`:

- **`CONFIG.BOT_USERNAME` / `CONFIG.SUPPORT_USERNAME`** — сейчас плейсхолдеры `reels_bot` / `reels_bot_support`. Заменить на реальные юзернеймы, когда бот будет зарегистрирован в BotFather — это единственное место, где они прописаны.
- **`OFFER`** — заголовок и подзаголовок главного экрана.
- **`TARIFFS`** — тарифная сетка (экран «Тарифы» и бейджи лимита везде).
- **`PROCESSING_STAGES`** — текст и % на экране обработки.
- **`SUBTITLE_STYLES` / `MUSIC_STYLES`** — варианты в нижней шторке на экране результата.
- **`HISTORY_SEED` / `DEFAULT_USER_STATE`** — стартовое состояние нового пользователя (сейчас: тариф «Бесплатный», 1 клип уже сделан, 2 свободных клипа осталось).

## Что здесь мок (и как заменить на реальный backend)

Видео-файл нигде не загружается по-настоящему — по требованию платформы (см. research.md, оценка Telegram-разработчика) приём файла всегда идёт через чат с ботом, а не через веб-форму.

| Что замокано в `app.js` | Как заменить |
|---|---|
| Демо-«видео» на главной и в результате | CSS/SVG-анимация (`.demo-loop` в `style.css`). Заменить на `<video>` с реальным клипом, когда он появится — верстка уже под это готова (тот же контейнер `demo-card__phone` / `result-card`). |
| `startProcessing()` — прогресс идёт по `setTimeout`, не по реальному статусу | Заменить тело функции на поллинг backend-эндпоинта статуса задачи (см. research.md: WebSocket в Mini App нет из коробки, только поллинг или сообщение от бота). |
| `handleUploadCta()` — сразу переходит к обработке после «открытия чата» | В реальном сценарии видео отправляется в чат, бот обрабатывает его и присылает сообщение с кнопкой `web_app`, которая открывает Mini App заново уже на экране `processing`/`result` с `id` конкретной задачи. |
| `handlePay()` — оплата ждёт 900мс и считается успешной | Заменить на `Telegram.WebApp.openInvoice()` с реальным `invoice_link`, полученным от backend через Bot API (`createInvoiceLink` с `currency: "XTR"` для Telegram Stars). |
| `loadState()` / `persistState()` — состояние пользователя живёт в `localStorage` браузера | Заменить на запросы к backend, авторизованные через `Telegram.WebApp.initData` (backend обязан проверять хэш `initData` перед тем, как доверять `user.id` — см. research.md). |
| Аватар/имя в профиле | Уже берутся из настоящего `Telegram.WebApp.initDataUnsafe.user`, если приложение открыто внутри Telegram — здесь ничего менять не нужно. Вне Telegram используется мок-пользователь «Алекс» (`js/telegram.js`, функция `getUser`). |

## Бренд-палитра (синхронизирована с сайтом)

Палитра, шрифт и декор **зафиксированы** и не подстраиваются под тему пользователя в Telegram (обычно Mini App так не делают, но здесь важнее визуальное единство с сайтом того же автора). Все токены — в `:root` в начале `style.css`: `--bg` (тёмно-синий `#050e1d`), `--accent` (пыльно-розовый `#e8a9bf`), шрифт `--font` (Montserrat, подключён через Google Fonts в `index.html`). `js/telegram.js` больше не копирует `Telegram.WebApp.themeParams` в CSS-переменные — только синхронизирует цвет системного хрома (`setHeaderColor`/`setBackgroundColor`) с этим же тёмно-синим.

## Декоративные иконки «из жидкого металла»

9 WebP-иконок в `img/` (`heart`, `sparkle`, `drop`, `moon`, `rings`, `star`, `blob`, `flower`, `cherry`) — те же ассеты, что использует сайт (были встроены туда как data-URI, здесь вынесены в обычные файлы). **Анимированы** двумя способами, как на сайте (`.obj__f` float / `.ico` spin), но мягче и медленнее — компактные акценты в мобильном интерфейсе, а не крупные декорации на просторном лендинге. Уважают `prefers-reduced-motion`.

- Стили — класс `.deco-icon` в конце `style.css` (даёт покачивание `@keyframes deco-float`), модификатор `.deco-icon--spin` вместо покачивания даёт вращение (`@keyframes deco-spin`, для «искристых» иконок — sparkle, star), модификатор картинки (`.deco-icon--heart` и т.д.) и модификатор позиции на конкретном экране (`.deco-pos--home-title` и т.д., там же CSS-переменные `--r0`/`--r1` — крайние углы покачивания, `--dur`/`--delay` — чтобы соседние иконки двигались не синхронно). Один инстанс = один `<img class="deco-icon deco-icon--X [deco-icon--spin] deco-pos--Y">` в `index.html`.
- Сейчас использованы (10 инстансов, 9 уникальных иконок, sparkle встречается дважды): sparkle-spin + drop (Главная), flower (Загрузка), moon + blob (Результат), cherry (Мои клипы), rings + star-spin (Тарифы), heart + sparkle-spin (Профиль).
- **Важно про позиционирование:** контейнер `.screen__content` — это `overflow-y:auto`, поэтому у иконок, стоящих в нём напрямую, `top`/`left` должны быть **≥ 0** (отрицательные значения обрезаются скроллом). Если нужно вылезти за край элемента (как drop на Главной или flower на Загрузке) — оборачивайте сам элемент в `position:relative` враппер (см. `.icon-circle-wrap`, `.demo-card`, `.home-header`) и уже внутри него используйте отрицательные отступы.
- **Чтобы добавить ещё** — на сайте таких иконок больше 20 (звёзды разных форм, шар, песочные часы, глаз, кудри, весна и т.д., все `.o-*` в исходнике сайта). Достать конкретную: найти на сайте строку вида `.o-имя .obj__f{background-image:url(data:image/webp;base64,...)}`, вырезать base64 после `base64,` до закрывающих `)}` и раскодировать (`base64 -d`) в `.webp` файл — так же, как это сделано для уже добавленных девяти.
- **Чтобы поменять позицию/скорость/размер** — правьте только `.deco-pos--*` в `style.css`, HTML и JS трогать не нужно.

## Как посмотреть

Открыть `index.html` в браузере (мобильная ширина — уменьшить окно до ~390px или включить режим устройства в DevTools). Вне Telegram SDK работает в safe-режиме: Main/Back Button показываются как обычные DOM-кнопки внутри экрана, тема — та же фиксированная тёмно-синяя, что и внутри Telegram.

Для проверки внутри настоящего Telegram — выложить папку на любой HTTPS-хостинг и указать URL в BotFather (`/newapp` или `/setmenubutton`).
